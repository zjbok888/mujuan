# P23 · 教师端与学生端拆成两个端口（核心迭代 1）

## 背景
两端共用一个端口，靠前端隐藏导航区分"学生视角"。问题：学生打开控制台直接调
`/api/assistant/chat` 就能让 AI 改老师的卷子——不是界面问题，是权限漏洞。

## 我的 Prompt（节选）
> 学生端和教师端要是两个端口，页面功能不一样，AI 功能也要相互独立。
> 不要只是把按钮藏起来，要让学生真的做不到。

## AI 的第一版方案（有缺陷）
在路由里加 `if (user.role !== 'teacher') return 403`。
我否掉了：**权限判断可以被漏加**，应该让路由根本不存在。

## 引导修正
> 用两个 Fastify app，学生端不注册生成/改题/学情/接入这些路由。
> 同一个 dist 产物，服务端按端口往 index.html 注入角色。

## 落地
- `server/app.ts` 按 `role` 分支注册路由；`server/index.ts` 起两个 listen。
- 交卷抽成 `routes/attempts.ts`，两端唯一共用写接口。
- 自检加"5 条教师端接口在学生端必须 404"。

## Bug 与修复
- 缓存了 `index.html` 导致重新构建后整站白屏（引用旧哈希资源）→ 改为每次请求读盘。
- verify 脚本仍在用教师端 app 调学生接口 → 改为 `studentApp.inject`。
