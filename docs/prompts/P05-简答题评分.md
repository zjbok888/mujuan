# P05 · 简答题评分：模型把"评分要点"写成了描述句

| 项 | 内容 |
|---|---|
| 目标 | 简答题不用模型判分，而用确定性的关键词细则 |
| 落点提交 | `4f2d29b`（评分器）、`06698be`（提示词约束） |
| 现象 | 学生答案全对，只拿到 63/97 |

## 1. 我给出的指令

> "简答题不许调模型打分——那样每次分数都可能不一样。
> 让模型给出 `keywordRubric`，评分器只做字面匹配，然后**所有简答题强制进教师复核队列**。"

这个设计的前提是：模型给出的 keyword 必须是**标准答案里真实出现的片段**。

## 2. 翻车（真实数据）

第一版提示词只写了"简答题必须给 keywordRubric，各项 points 之和等于该题分值"。
模型很听话地给了 16 条，长这样：

```
{ "keyword": "正确求出 $f'(x)=x^{2}-(a+1)x+a=(x-1)(x-a)$", "points": 2 }
{ "keyword": "说明 $a=2$ 时 $f'(x)$ 在 $[1,2]$ 上不恒为零，符合单调递减", "points": 1 }
```

全是**描述性句子**。评分器拿标准答案去 `includes()` 这些句子，一条都命中不了，
于是"全部答对"的试卷只得了 63 分。

## 3. 修正

提示词里把这条写成硬性约束：

```
keyword 必须是从 answers[0] 中【原样截取】的 2-10 字片段
（如 "极大值"、"$a\\ge 2$"、"单调递增"），
绝不允许写成"正确求出…""说明…"这类描述性长句——评分程序只做字面匹配。
```

重新录制后，17 条细则变成了 7 条短片段：

```
0<x<6 / 单调递增 / 单调递减 / 极大值 / V(2)=128 / x=2 / 128
```

标准答案逐条命中 7/7，全对得分 97/97。

## 4. 复盘

这不是"模型不听话"，是**接口契约没写清楚**。
当评分器只能做字面匹配时，"keyword 必须是答案的子串"就是接口的一部分，
必须写进提示词，而不是指望模型猜到。

顺带把评分器的不确定性也钉死了：同一份卷子、同一份作答，`gradePaper` 的输出必然相等（有单测覆盖）。
