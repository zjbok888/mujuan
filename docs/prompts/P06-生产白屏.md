# P06 · 生产模式白屏：一个选项让所有静态资源 404

| 项 | 内容 |
|---|---|
| 目标 | `npm run build && npm start` 之后，评委打开浏览器就能用 |
| 落点提交 | `f634f25`（修复并入该提交） |
| 现象 | 页面纯白，控制台无报错 |

## 1. 我给出的指令

> "生产模式必须只占一个端口：API 进程同时托管前端产物。
> 评委机器上只需要 build + start 两条命令。"

Fastify 侧用 `@fastify/static` 托管 `dist/`。

## 2. 翻车（真实发生）

开发模式（Vite dev server 5173）一切正常，
切到生产模式后打开 `http://127.0.0.1:4000`，得到一张纯白页面。

排查：

```bash
curl -s -o NUL -w "%{http_code}" http://127.0.0.1:4000/assets/index-xxxx.js
# 404
```

首页 HTML 能返回，但它引用的 `/assets/*.js`、`/assets/*.css` 全部 404 —— 白屏。

根因在这一行：

```ts
await app.register(fastifyStatic, { root: config.webDist, wildcard: false })
```

`wildcard: false` 关掉了通配路由，结果是只有根路径能被服务，
**整个 assets 目录都不再可达**。当时的直觉是"少开一个通配路由更安全"，
实际效果是把应用打断了腿。

修正：

```ts
// 不要关掉 wildcard：关掉之后只有 "/" 能被服务，/assets/* 全部 404，页面白屏
await app.register(fastifyStatic, { root: config.webDist, prefix: '/' })
```

修完后同一张截图才第一次真正出现——之前那几张"空白截图"其实就是这个 bug 的直接证据。

## 3. 复盘

这个 bug 只在"生产构建 + 单进程托管"这条路径上出现，
而开发模式永远暴露不出来。**所以我给自己定了一条规矩：
每次改完都要用生产模式截一次图，而不是只看 `npm run dev`。**

顺带说一句：为了截图写了 `scripts/shot.mjs`（CDP 驱动），
它后来成了整个项目文档配图的固定工具。
