# P04 · 演示模式不是"放录像"：回放通道必须自己算账

| 项 | 内容 |
|---|---|
| 目标 | 断网、无 Key、无预算的机器上也能完整演示闭环 |
| 落点提交 | `3105780` feat(infra): 演示模式回放，保证断网无 Key 也能完整演示 |

## 1. 我给出的指令

> "演示数据必须来自一次**真实生成**，不许手写假题。
> 回放时要保留阶段切换、字段校验与评分链路，只是把延迟压下去。"

于是有了 `scripts/record-demo.ts`：真实调一次模型，把 `PaperIR` 落盘成 `fixtures/demo-paper.json`。

## 2. 首版方案与两次翻车

**第一版**：回放时按顺序切片——第 1 批取前 2 题，第 2 批取下 2 题。

评委只要把题型配比从"4 单选 2 填空 1 简答"改成"3 单选 1 简答"，立刻出事：
第 3、4 题本来是单选，却被塞进了要求"填空题"的题位，
于是填空题带着选项、答案对不上，校验直接报错。

修正一：**按题型分队列**。从题位清单里解析出"这一批要什么题型"，
再从对应队列取题；并加了 `clampMixToDemo()`——超出样例能力的题量自动收窄，
而不是生成一份自相矛盾的卷子。

**第二版**：题型对上了，但简答题还是报错：

```
RUBRIC_POINTS_MISMATCH  细则分值合计 38，与题目分值 57 不一致
```

因为分值由系统重新分配（3 单选 + 1 简答，简答被分到 57 分），
而样例里的评分细则之和还是录制时的 38 分。

修正二：回放时按目标分值**等比缩放细则**，余数补给分值最高的条目（`rescale()`）。

## 3. 现在的结果

同一份样例可以支撑任意题型配比（只要不超过样例题量），
`npm run verify` 里专门有一条"无 Key 回放具备确定性"：两次回放题干完全一致。

## 4. 复盘

"演示模式"最容易做成看起来能跑、一改参数就露馅的样子。
真正的验收标准是：**评委随手改参数，系统仍然自洽**。
